爬虫来看了一眼，和把你放进数据库是两码事

这里有两个概念：抓取（爬虫顺着网线爬进来看了一眼）和收录（爬虫觉得你写得还行，把你放进了搜索数据库里）。

门口的保安告示，和门后的纸条

有几个点必须看紧了，如果你做的网页是企业内部站点，更要注意了：

  • robots.txt：这是门口的保安告示，如果上面写了禁止爬虫访问，爬虫扭头就走；
  • noindex：这是贴在门后的纸条，意思是“你可以进来看，但别把我登报纸上”；
整理补充：noindex 必须能被爬虫读取，robots 禁抓可能让它读不到该规则。内部资料需要身份认证与访问权限，robots 和 noindex 都不是安全门锁。 · Google：robots.txt 的用途与限制 · Google：noindex 的生效条件

给爬虫带路的菜单，别塞一堆错误地址

  • sitemap.xml（站点地图）：相当于一张给爬虫带路的菜单，告诉它你家都有哪些好菜；
  • HTTP 状态码：正常就该是标准的 200，删掉的页面就利索地给 404，别整那些稀奇古怪的跳转。

记住两点：提交了站点地图不等于保送收录；另外，别以为在 robots.txt 里把网页锁了就能彻底防收录，想彻底不让搜到，规规矩矩加 noindex。

整理补充：状态码应反映真实情况：正常内容、迁移、不存在和临时故障分别处理。地图提供发现线索，不能保证索引。 · Google：站点地图

花里胡哨看够了，正文却是一张白纸

现在的开发老哥都喜欢用 Vue 或 React 搞单页应用（SPA），看着各种动效很炫，但对爬虫来说就是：😡 你是在难为我，我只看代码，看文字，不是来看你花里胡哨。

为什么？因为有时候浏览器打开要等半天 JavaScript 加载数据，搜索引擎爬虫耐心很差，如果接口卡一下或者脚本报错，它抓到的可能就是一张白纸。

怎么避坑？

  • 做核心业务和文章页面，老老实实用服务端渲染（SSR）或者预渲染，让服务器吐出来的第一波 HTML 源码里就有大白话正文。
整理补充：Google 可以执行 JavaScript；原文的“白卷”说的是脚本、接口或访问条件导致正文缺失的风险。SSR/预渲染也要检查实际输出，不能只看框架名称。 · Google：JavaScript SEO

爬虫得顺着真正的链接一页一页逛

  • 页面跳转要用规规矩矩的 <a href="/courses/ai-office"> 链接，千万别偷懒用那种点击事件或者 #/courses 这类带井号的哈希路由，爬虫顺着真正的链接才能一页一页逛下去。

不知道收没收录，先把检查口径弄清楚

国内站看百度搜索资源平台，海外看 Google Search Console（GSC），有了后台，你就不用瞎猜，看数据对症下药：

  • 页面根本没收录：先查代码是不是把爬虫挡了，或者页面是不是空白没渲染出来，还是不知道，用 site:网址；
整理补充：site: 可以粗看，结果和数量并非完整、精确的索引库存；关键页面结合站长平台的 URL 检查和实际响应核对。 · Google：site: 查询的边界

示例 · 不同目标使用不同控制

生产公开页、公开但不参与搜索的页面、受权限保护的内部页，需要分别配置。以下仅示意 noindex 与普通链接，不能把 noindex 用作内部资料的访问保护。

<!-- 仅用于希望公开可访问、但不希望被索引的页面 -->
<meta name="robots" content="noindex">

<!-- 核心页面使用可解析链接；目标应能直接访问 -->
<a href="/guides/deploy">查看部署条件与检查步骤</a>

把这一讲用到自己的业务

  1. 确认公开范围先确认页面本来就适合对外公开。内部资料保持权限，必要时单独制作公开说明，不为索引盲目移除认证。
  2. 核对响应同时检查状态与正文，测试正常、迁移和不存在的路径。对 JavaScript 页面比较初始响应和渲染结果。
  3. 核对规则检查 robots、noindex、规范地址和地图是否与目标一致。记录实际读到的规则，不只看后台配置界面。
  4. 复查处理完成必要修改后记录版本，再通过站长工具和实际访问复查。索引与排名另行观察，不把提交按钮当完成证明。

本节交付：一份逐 URL 的技术证据表，包含访问条件、响应、渲染、抓取与索引规则，以及修改后的复查记录。
